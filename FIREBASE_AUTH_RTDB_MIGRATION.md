# Firebase Auth & Realtime Database Migration Guide

## Overview

This guide explains the changes made to Moxlite V2 Beta to integrate **Firebase Auth** for authentication and **Firebase Realtime Database** for activity history tracking.

## Changes Made

### 1. Core Firebase Configuration (`src/lib/firebase.ts`)

**What changed:**

- Added import for Firebase Realtime Database (`getDatabase`)
- Added environment variable `NEXT_PUBLIC_FIREBASE_DATABASE_URL`
- Exported `rtdb` (Realtime Database reference)

**Impact:**

- ✅ Enables real-time activity tracking
- ✅ No breaking changes to existing auth functionality

### 2. Activity Tracking Service (`src/lib/activityTracker.ts`)

**What changed:**

- Replaced API-based tracking with Firebase Realtime Database writes
- Changed `timestamp` from `Date` object to Unix timestamp (`number`)
- Activities now written to three locations:
  - `/user_activities/` - Global activity log
  - `/users/{userId}/activities/` - User-specific log
  - `/activities_by_date/{YYYY-MM-DD}/` - Daily activity log

**Migration Steps:**

```typescript
// Before (API call)
await fetch("/api/tracking/log-activity", { method: "POST", body: ... })

// After (Direct Firebase write)
const activitiesRef = ref(rtdb, "user_activities");
await push(activitiesRef).set(activity);
```

**Benefits:**

- ✅ No server round-trip needed
- ✅ Real-time updates across clients
- ✅ Better performance for high-volume tracking
- ✅ Simpler deployment (no API maintenance)

### 3. New Activity History Service (`src/lib/activityHistoryService.ts`)

**New file** with utilities to query activity history:

```typescript
// Get user activities
await ActivityHistoryService.getUserActivities(userId, limit);

// Get activities by date
await ActivityHistoryService.getActivitiesByDate("2024-01-15");

// Get activities by action
await ActivityHistoryService.getActivitiesByAction("login");

// Real-time listener
ActivityHistoryService.onUserActivitiesChange(userId, callback);

// Get statistics
await ActivityHistoryService.getUserActivityStats(userId);
```

### 4. Documentation Updates

- Updated `FIREBASE_SETUP.md` with new configuration requirements
- Added Firebase Security Rules examples
- Included troubleshooting guide

## How to Upgrade

### Step 1: Update Environment Variables

1. Open `.env.local`
2. Add `NEXT_PUBLIC_FIREBASE_DATABASE_URL`
3. Get it from: Firebase Console → Realtime Database → Copy URL

```env
NEXT_PUBLIC_FIREBASE_DATABASE_URL=https://your-project-id.firebaseio.com
```

### Step 2: Update Firebase Security Rules

Go to Firebase Console → Realtime Database → Rules and set:

```json
{
  "rules": {
    "user_activities": {
      ".read": "root.child('admins').child(auth.uid).exists()",
      ".write": false
    },
    "users": {
      "$uid": {
        "activities": {
          ".read": "auth.uid === $uid || root.child('admins').child(auth.uid).exists()",
          ".write": "auth.uid === $uid"
        }
      }
    },
    "activities_by_date": {
      ".read": "root.child('admins').child(auth.uid).exists()",
      ".write": false
    }
  }
}
```

### Step 3: Test Activity Tracking

1. Start your app: `npm run dev`
2. Login with Firebase Auth
3. Navigate around the app
4. Open Firefox DevTools → Storage → Firebase Database
5. Verify activities are being saved

### Step 4: Remove Old API Code (Optional)

If you're no longer using API-based tracking:

```bash
# Remove old tracking API files
rm src/pages/api/tracking/log-activity.ts
rm src/pages/api/tracking/analytics.ts
```

## Data Structure

### Activity Document Format

```typescript
{
  id: string;                    // Generated by Firebase
  userId: string;               // Firebase Auth UID or "anonymous"
  userEmail?: string;           // User email
  action: string;               // "page_access", "download", "login", etc.
  actionDetails: {
    page?: string;              // Current page/route
    fileName?: string;          // Downloaded file name
    documentType?: string;      // Document type
    currentPath?: string;       // Browser path
    currentUrl?: string;        // Full browser URL
    language?: string;          // Browser language
    timezone?: string;          // User timezone
    viewport?: string;          // Screen resolution
    [key: string]: unknown;    // Additional details
  };
  timestamp: number;            // Unix timestamp in milliseconds
  userAgent?: string;           // Browser user agent
  ipAddress?: string;           // User IP (if captured server-side)
  sessionId: string;            // Unique session ID
}
```

## Using Activity History in Components

### Example: User Activity Dashboard

```typescript
'use client';

import { useEffect, useState } from 'react';
import { useAuth } from '@/lib/authContext';
import { ActivityHistoryService } from '@/lib/activityHistoryService';

export function ActivityDashboard() {
  const { user } = useAuth();
  const [activities, setActivities] = useState([]);

  useEffect(() => {
    if (!user) return;

    // Real-time listener
    const unsubscribe = ActivityHistoryService.onUserActivitiesChange(
      user.uid,
      setActivities
    );

    return unsubscribe;
  }, [user?.uid]);

  return (
    <div>
      <h2>Your Activity History</h2>
      {activities.map((activity) => (
        <div key={activity.id}>
          <p>{activity.action} at {new Date(activity.timestamp).toLocaleString()}</p>
          <p>Page: {activity.actionDetails.page}</p>
        </div>
      ))}
    </div>
  );
}
```

### Example: Admin Analytics

```typescript
'use client';

import { useEffect, useState } from 'react';
import { ActivityHistoryService } from '@/lib/activityHistoryService';

export function AdminAnalytics() {
  const [summary, setSummary] = useState(null);

  useEffect(() => {
    async function loadSummary() {
      const start = new Date();
      start.setDate(start.getDate() - 30); // Last 30 days

      const end = new Date();

      const data = await ActivityHistoryService.getActivitySummary(start, end);
      setSummary(data);
    }

    loadSummary();
  }, []);

  return (
    <div>
      <h2>Activity Summary (Last 30 Days)</h2>
      <p>Total Activities: {summary?.totalActivities}</p>
      <p>Unique Users: {summary?.uniqueUsers.size}</p>
      <pre>{JSON.stringify(summary?.actionSummary, null, 2)}</pre>
    </div>
  );
}
```

## Troubleshooting

### "Database URL not configured" error

**Solution:**

1. Add `NEXT_PUBLIC_FIREBASE_DATABASE_URL` to `.env.local`
2. Restart your dev server

### Activities not appearing in Realtime Database

**Solution:**

1. Check Firebase Security Rules - ensure `.write` is allowed for authenticated users
2. Check browser console for errors
3. Verify user is authenticated: `console.log(user)` in component

### Real-time listener not updating

**Solution:**

```typescript
useEffect(() => {
  if (!user?.uid) return; // Must have user ID

  // Subscribe
  const unsubscribe = ActivityHistoryService.onUserActivitiesChange(
    user.uid,
    callback,
  );

  // Unsubscribe on cleanup
  return unsubscribe;
}, [user?.uid]); // Depend on user.uid
```

## Performance Considerations

- **Per-user queries**: Use `getUserActivities()` - Optimized for single user
- **All activities**: Use `getAllActivities()` - Admin only, use pagination
- **Real-time updates**: Use `onUserActivitiesChange()` - Efficient listeners
- **Batch queries**: Combine multiple requests into one

## Rollback Plan

If you need to rollback to the old API-based system:

1. Keep old activity tracker code in version control
2. Keep API endpoints (`log-activity.ts`, `analytics.ts`)
3. To rollback: revert to previous commit
4. Remove `NEXT_PUBLIC_FIREBASE_DATABASE_URL` from `.env.local`
